# Facts-only experiment: failure facts as a standalone memory channel

## What we tested

Whether failure facts (short template-generated "avoid" lessons from past failed reproduce attempts) help later tasks generate correct reproduction tests, when facts are the **only** memory available - no demonstrations, no episodic examples.

## Background

ExpeRepair has two memory types:

- **Demos** (episodic memory): full test scripts or patches from past issues, retrieved by BM25 similarity and pasted into the prompt.
- **Facts** (semantic memory): compressed warnings extracted from failed attempts, like "a test for task X failed with ModuleNotFoundError."

Phase 4 generated 10 failure facts from 22 Django tasks. The facts sat in `lessons.jsonl` files but were never tested as a standalone channel.

## Implementation

Added a new `--memory-mode facts` option that:

- Disables demo retrieval entirely.
- Loads all prior repo-wide failure facts from `lessons.jsonl`.
- Injects them into the `{summarized_rules}` slot of the system prompt via `SYSTEM_PROMPT_W_RULE`.
- Builds the prompt thread via `_construct_init_thread_exp`.

The prompt the model sees:

```
You are an experienced software engineer responsible for writing a test
script for an issue reported in your GitHub project django.

Here are some experiences drawn from other issues in your project that
may provide valuable insights for writing tests for this issue:

Failure facts from previous issues:
- Task django__django-11019: avoid tests that raise unknown
- Task django__django-11039: avoid tests that raise ModuleNotFoundError
- Task django__django-11133: avoid tests that raise unknown
...
```

Files changed:

- `config.py`: added `"facts"` to accepted memory_mode values.
- `memory_gate/gate.py`: added `MemoryGateMode.FACTS`.
- `agents/agent_reproducer.py`: added `_call_api_reproduce_facts_only()` and wired it into `_write_reproducing_test_W_EXP`.
- `inference/reproduce_initial.py`, `generate_initial.py`, `generate_w_memory.py`: accept `"facts"` in argparse choices.
- `task.py`: egg-link cleanup for pip<21 in the testbed conda env.

## Experiment

Ran `reproduce_initial.py --memory-mode facts` on all 22 Django tasks in the dev slice (`django__django-10914` to `django__django-11964`).

Model: `gpt-5.6-luna` via Codemate proxy (same as Phase 0/1 baseline).
Runtime: ~22 minutes total.
Cost: ~$0.30 total.

Compared results against the Phase 1 baseline, which used the default demo retrieval (`--memory-mode baseline`).

### The 5 tasks that improved

These 5 tasks had tests the judge rejected in Phase 1 but accepted under facts-only. The failure-mode warnings in the system prompt gave the model enough signal to avoid the bad patterns that caused earlier tests to fail.

- django-11019: was a `confirmed_failure` with `unknown` exception. Test improved from NO to YES.
- django-11283: was a `confirmed_failure` with `ModuleNotFoundError`. Test improved from NO to YES.
- django-11422: was `unsafe` (contained `exec`/`compile` calls). Test improved from NO to YES.
- django-11564: was a `confirmed_failure` with `unknown` exception. Test improved from NO to YES.
- django-11583: was a `confirmed_failure` with `unknown` exception. Test improved from NO to YES.

### The 2 tasks that stayed NO

- django-11620: had facts available (all 6 prior repo-wide facts). The test code still failed in ways the facts did not cover.
- django-11910: had facts available including an `AttributeError` fact. The test still failed with a different error.

### Fact quality

Of the 10 facts generated by Phase 4:

- 3 had `ModuleNotFoundError` - actionable, specific.
- 1 had `AttributeError` - actionable, specific.
- 7 had `unknown` - too weak to help.

The 5 improved tasks all had facts available. But the `unknown` facts could not have been the direct cause of improvement in most cases, since "avoid tests that raise unknown" is not directional. The improvement likely came from the system prompt framing ("here are some experiences") causing the model to be more careful about testing conventions, rather than from the specific fact content.

## What this means

Facts-only matches demos on all 15 tasks that already passed, and improved 5 of 7 tasks that previously failed. The net effect is a reproduce rate increase from 68% to 91%.

Two interpretations:

1. Facts meaningfully guided the model away from bad patterns.
2. The system prompt framing alone ("here are some experiences drawn from other issues") caused more cautious test generation, regardless of fact content.

These can be distinguished by running `--memory-mode facts` with empty facts (no `lessons.jsonl` files) to isolate the framing effect.
